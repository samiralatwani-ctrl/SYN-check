# المرحلة ٢ — الباركود والنتيجة

## ما بُني
| الجزء | المكان |
|---|---|
| منطق الباركود (رقم التحقق، التطبيع إلى GTIN-14، تحليل GS1 DataMatrix) | `packages/gs1` |
| محرك القواعد بلغة TypeScript (يعيد إنتاج الحالات الـ29 في `method/v1/cases.yaml`) | `packages/rules-engine` |
| دوال القراءة العامة `lookup_gtin` و`search_products` | `supabase/migrations/20261109000500_public_lookup.sql` |
| تطبيق الهاتف (Expo SDK 58): المسح، والنتيجة والأسباب، وماذا أفعل الآن، وعن المنهج، والإعدادات | `apps/mobile` |

## معيار القبول
"باركود صحيح غير موجود في القاعدة يعطي غير كافٍ للحكم وليس مطابق": مُختبر في `apps/mobile/test/scan.test.ts` (phase 2 acceptance).

## تشغيل التطبيق
```bash
cd apps/mobile
cp .env.example .env            # ضع رابط Supabase ومفتاح anon، أو EXPO_PUBLIC_SYN_FIXTURES=1 لوضع العرض
npx expo start                  # ثم امسح رمز QR بتطبيق Expo Go على الهاتف
```
وضع العرض يستخدم بيانات TEST_ فقط، ويُظهر شريطاً واضحاً بذلك.

## حدود هذه المرحلة
- لا توجد أرقام GTIN رسمية في القاعدة بعد، فمنتجات IQB كلها تعطي "غير كافٍ للحكم" عند مسح الباركود. هذا صحيح منهجياً.
- إنذارات TİTCK التي تحمل باركوداً (27 منتجاً) تعطي "غير مطابق" فوراً.
- الإنذار لتشغيلة محددة يحتاج قراءة التشغيلة من DataMatrix، أو من الملصق في المرحلة ٣. قبل ذلك يُعرض كتنبيه "قارن رقم التشغيلة".
- السجل المحلي وحفظ الفحوص في القاعدة يأتيان مع الحسابات في مرحلة لاحقة. النتيجة الآن في ذاكرة التطبيق فقط.
- الكردية (سوراني وكرمانجي) لم تُترجم بعد. التركية مترجمة للشاشات الأساسية، ويلزمها مراجعة متحدث أصلي.
